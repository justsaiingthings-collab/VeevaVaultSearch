Why VaultSearch

The six problems it solves

"I can't find documents unless I know exact names"

Native Vault search requires knowing the precise document title or ID.

→ Query templates + structured filters

"Too many irrelevant results"

Keyword search returns everything — including drafts, obsolete, and unrelated documents.

→ VQL pre-filtering + MDL constraints

"Version confusion — draft vs approved vs old"

Users pull outdated versions without realising a newer approved version exists.

→ Latest-version grouping + lifecycle state labels

"I don't know what to search for"

New team members and auditors don't know Vault's document taxonomy or naming conventions.

→ Rule-based recommended query chips

"Audit and compliance searches are painful"

Building inspection-ready document packages requires manual, repetitive search work.

→ Pre-built compliance and audit query packs

"Search feels like writing database queries"

Power users resort to raw VQL. Everyone else gives up.

→ UX abstraction layer via Vault SDK
How it works

Up and running in minutes

1

Connect your Vault

Enter your Vault domain and authenticate with username/password or OAuth 2.0 SSO.

2

Deploy the proxy

One command deploys a Lambda proxy to your AWS account. Free tier covers MVP usage.

3

Search with intent

Pick from recommended query chips or type naturally. VQL is built and executed automatically.

4

Get auditable results

Every query is deterministic, version-aware, and permission-safe. No AI, no hallucinations.
